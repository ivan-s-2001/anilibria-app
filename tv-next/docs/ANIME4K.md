# Anime4K: изучение v4.x и перенос в Media3

Снимок Anime4K: `7684e9586f8dcc738af08a1cdceb024cc184f426`.

## Что используется как источник

- [Advanced Usage Instructions v4.x](https://github.com/bloc97/Anime4K/blob/master/md/GLSL_Instructions_Advanced.md).
- [Официальный Windows Low-end input.conf](https://github.com/bloc97/Anime4K/blob/master/md/Template/GLSL_Windows_Low-end/input.conf).
- Исходники шейдеров `glsl/Restore`, `glsl/Upscale`, `glsl/Upscale+Denoise`.
- Media3 1.8.0: `GlEffect`, `BaseGlShaderProgram`, `DefaultVideoFrameProcessor`, `DefaultShaderProgram` и SDR-шейдеры преобразования цвета.

Важное уточнение: официальные пресеты v4 используют некоторые шейдеры, в имени DESC которых остаётся v3.2, включая Upscale CNN. Это само по себе не ошибка и не признак несовместимости. Главные недостатки первой реализации — отсутствие полной цепочки, игнорирование WHEN/размеров, отсутствие восстановления и ограничителя светлых ореолов, недостаточная точность результата.

## Что означают режимы

Режим выбирается по виду дефектов, а не автоматически по разрешению. Надписи «A — 1080p», «B — 720p», «C — 480p» являются только приблизительными подсказками. Официальное руководство рекомендует сравнивать A, B, C на одном изображении.

| Режим | Основная цепочка | Назначение и ограничения |
| --- | --- | --- |
| A | Restore → Upscale → Upscale | Более заметное восстановление размытых линий, артефактов пересэмплирования и сжатия. Может усиливать ореолы, полосы на градиентах и смазывать текстуры. |
| B | Restore_Soft → Upscale → Upscale | Более мягкая работа с уменьшенным изображением, алиасингом и ореолами. Часть размытия может остаться; текстуры тоже могут сглаживаться. |
| C | Upscale_Denoise → Upscale | Увеличение с шумоподавлением. Подходит для ряда уменьшенных источников и чистых изображений, но не заменяет восстановление A/B и может усиливать отдельные артефакты. |
| A+A | Restore → Upscale → Restore → Upscale | Повторное восстановление после увеличения. Более высокая нагрузка; риск перешарпа, ореолов, полос и алиасинга. Только при масштабе от ×2. |
| B+B | Restore_Soft → Upscale → Restore_Soft → Upscale | Повторная мягкая обработка. Только при масштабе от ×2. |
| C+A | Upscale_Denoise → Restore → Upscale | Шумоподавление и затем восстановление. Только при масштабе от ×2. |

Для A/B восстановление имеет смысл и при 1080p → 1080p. Запрещать всю обработку при масштабе ×1 было неправильно. Для сохранённого усиленного режима при масштабе меньше ×2 применяется соответствующий основной: A+A → A, B+B → B, C+A → C. Это поведение объяснено в модалке; недоступные усиленные режимы нельзя выбрать, а пункт настроек показывает фактический основной режим.

Число upscale-этапов в пресете не означает обязательное увеличение в четыре раза для каждого видео. `WHEN` проверяет нужный масштаб: второй Upscale может быть пропущен, если разрешения первого достаточно.

## Точный порядок официального быстрого пресета

Взяты варианты M для первого восстановления/увеличения и S для более дорогой обработки увеличенного изображения. Это официальный быстрый профиль для настольных GPU, а не обещание достаточной скорости на Android TV.

| Режим | Файлы в порядке выполнения |
| --- | --- |
| A | Clamp_Highlights, Restore_CNN_M, Upscale_CNN_x2_M, AutoDownscalePre_x2, AutoDownscalePre_x4, Upscale_CNN_x2_S |
| B | Clamp_Highlights, Restore_CNN_Soft_M, Upscale_CNN_x2_M, AutoDownscalePre_x2, AutoDownscalePre_x4, Upscale_CNN_x2_S |
| C | Clamp_Highlights, Upscale_Denoise_CNN_x2_M, AutoDownscalePre_x2, AutoDownscalePre_x4, Upscale_CNN_x2_S |
| A+A | Clamp_Highlights, Restore_CNN_M, Upscale_CNN_x2_M, Restore_CNN_S, AutoDownscalePre_x2, AutoDownscalePre_x4, Upscale_CNN_x2_S |
| B+B | Clamp_Highlights, Restore_CNN_Soft_M, Upscale_CNN_x2_M, AutoDownscalePre_x2, AutoDownscalePre_x4, Restore_CNN_Soft_S, Upscale_CNN_x2_S |
| C+A | Clamp_Highlights, Upscale_Denoise_CNN_x2_M, AutoDownscalePre_x2, AutoDownscalePre_x4, Restore_CNN_S, Upscale_CNN_x2_S |

Здесь у файлов опущено общее имя Anime4K и расширение .glsl. Точное соответствие списка файлов проверяется тестом по копии официального `input.conf`.

`Clamp_Highlights` сохраняет статистику исходного изображения в MAIN, а ограничивает яркость позже, в PREKERNEL. Нельзя просто выполнить весь файл в начале: финальный clamp должен увидеть уже обработанное изображение. Статистика должна сохраниться до этого прохода.

`AutoDownscalePre_x2` срабатывает при нужном масштабе от 1.2 до 2 и приводит промежуточное изображение к выходному размеру. `AutoDownscalePre_x4` при масштабе от 2.4 до 4 подготавливает половину выходного размера перед последним увеличением. Используются строгие условия из исходников. Например, при ×3 сначала выполняется точный ×2, затем уменьшение до ×1.5 исходного размера, затем ещё точный ×2. Нельзя сразу изменить выход CNN с ×2 на произвольный ×1.5: это нарушает смысл Depth-to-Space.

## Дополнительные шейдеры и варианты моделей

| Тип | Назначение | В текущих пресетах |
| --- | --- | --- |
| Restore / Restore_Soft | Восстановление линий; Soft ориентирован на артефакты уменьшения и алиасинг. | Да, по режиму. |
| Upscale | Увеличение ×2 уже подготовленного изображения. | Да. |
| Upscale_Denoise | Совместное увеличение ×2 и шумоподавление без отдельного дополнительного denoise-прохода. | В C и C+A. |
| Denoise | Отдельное шумоподавление. | Нет: официальный выбранный профиль его не добавляет. |
| Deblur | Отдельная коррекция размытия, по описанию автора без overshoot/ringing. | Нет. |
| Darken | Затемнение предполагаемых линий, иногда затрагивает другие детали. | Нет: это вкусовой эффект, а не обязательное улучшение. |
| Thin | Утончение предполагаемых линий, тоже может менять другие детали. | Нет. |
| Clamp_Highlights | Ограничение светлых выбросов по сохранённой исходной статистике. | Да, со специальным PREKERNEL-проходом. |
| AutoDownscalePre | Согласование промежуточного разрешения с выходным перед следующим увеличением. | Оба варианта, с исходными WHEN. |

S/M/L/VL/UL — размеры моделей и цена вычислений, а не режимы A/B/C и не качество исходного потока. Более крупная модель не гарантирует лучший результат для неподходящего режима. В текущем интерфейсе варианты модели отдельно не выбираются: используется официальный быстрый профиль M/S.

Руководство запрещает повторять один и тот же файл дважды в mpv без разделения имён: возможны конфликты сохранённых текстур и лишняя работа. Выбранный официальный профиль использует разные M/S-файлы для повторного Restore/Upscale. Дополнительно адаптер фиксирует отдельные версии результатов каждого прохода, а не читает «последнюю текстуру с таким именем» во время рендеринга.

## Что изменено в адаптере

1. Вместо одиночных DoG/CNN — шесть полных пресетов с Restore/Restore_Soft/Upscale_Denoise.
2. Планировщик исполняет WHEN, WIDTH, HEIGHT в обратной польской записи с MAIN, NATIVE, OUTPUT и сохранёнными текстурами.
3. MAIN обновляется после каждого изменения изображения; HOOKED связан с текущим MAIN. Повторные CNN-проходы получают отдельные версии текстур, поэтому не используют устаревшие карты признаков.
4. PREKERNEL отложен до конца основной обработки. Статистика STATSMAX сохраняется до clamp.
5. Переход между линейным SDR Media3 и гамма-кодированным RGB моделей выполняется только на границах всей цепочки. Все внутренние интерполяции и CNN-проходы работают в одном гамма-кодированном пространстве.
6. Все собственные промежуточные текстуры и выходной пул используют RGBA16F: сохраняются отрицательные признаки CNN, результат не квантуется дополнительно в RGBA8 перед обратной гаммой.
7. Буферы переиспользуются после последнего потребителя. Проверяются предел размера текстур GPU и бюджет собственных текстур 256 MiB, включая выходной пул. При превышении — отключение эффекта, без скрытой подмены алгоритма.
8. Старые значения light/quality больше не включают обработку автоматически: они интерпретируются как «Выключено».

## Что эта реализация не гарантирует

Это перенос пресетов и GLSL, а не встраивание mpv/libplacebo целиком. Финальное представление и масштабирование выполняются Media3; их фильтр масштабирования, вывод цветов и разрешение видеоповерхности могут отличаться от mpv. Автоматический выбор лучшего режима по содержимому не реализован.

RGBA16F внутри эффекта устраняет дополнительную 8-битную квантизацию в собственном выходе. Однако исходное декодирование, входная текстура Media3 и SDR-вывод могут иметь собственные ограничения точности. Нельзя обещать полное отсутствие banding или битовую идентичность mpv только на основании исправления выходного пула.

Поддерживается SDR. HDR не направляется через SDR-модели: ошибка инициализации отключает эффект и восстанавливает обычное воспроизведение. Обычная сетевая ошибка не сбрасывает настройку.

Нужны OpenGL ES 3, floating-point render targets и достаточная память. Второй Restore на ×2-изображении обрабатывает в четыре раза больше пикселей. Согласно руководству, переход S → M → L → VL → UL примерно удваивает время на каждом шаге; это ориентир, а не измерение на конкретном телевизоре. Бюджет всего кадра: около 41.7 мс для 24 fps, 33.3 мс для 30 fps, 16.7 мс для 60 fps. Декодирование, синхронизация и вывод тоже занимают время.

Выключено по умолчанию. Гарантии визуального улучшения для любого источника нет. Неподходящий режим может сделать изображение хуже даже при технически правильном выполнении.

## Проверки

- Списки файлов всех шести пресетов сравниваются с официальным input.conf.
- Проверены восстановление при ×1, ограничения усиленных режимов, WHEN и размеры при ×1.5/×2/×3/×4.
- Проверены порядок PREKERNEL и зависимости версий текстур.
- Все шесть режимов прошли пробный рендеринг в Mesa при пяти масштабах (30 цепочек): ровный цвет, контрастный край, тёмный градиент, отсутствие NaN/Inf и корректная альфа. Компилируется 51 уникальная шейдерная программа.
- Компиляция и рендеринг не являются подтверждением улучшения качества на реальном аниме или достаточной скорости телевизора.

На устройстве нужно сравнить выключено/A/B/C на одинаковом кадре, в том числе лица, тонкие линии, фоновые текстуры и тёмные градиенты; затем проверить плавность и усиленные режимы при увеличении от ×2. Нужны одинаковые источник, качество потока и позиция. Сначала первичные режимы, затем соответствующий усиленный.
