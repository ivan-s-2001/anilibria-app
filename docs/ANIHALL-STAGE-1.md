# AniHall: первый этап, телефон и ТВ

## Результат

Основа — `rewrite/tv-next` форка `ivan-s-2001/anilibria-app`. Рабочая ветка — `feature/anihall-yummytv-structure`.

В APK добавлены отдельные Android и Leanback launcher entrypoints. Телефон запускает `mobile.MobileActivity`, телевизор — существующую `MainActivity`. Мобильная часть написана заново поверх общего API; исходники и графика YummyTV не копировались. GPL и сведения об исходном форке сохранены.

## Структура

- `AppModel`: общие состояния, загрузка данных, стек переходов и пагинация. Переименован из `TvModel`, используется обеими Activity.
- `Api` / `AccountTransport`: запросы только к AniLiberty v1.
- `HomeModels`, `ReleaseModels`: модели, не вложенные в сетевой клиент.
- `PageRow`, `HomeRows`, `ReleaseRows`: сборка TV-представления отдельно от Activity.
- `PlaybackOrder`, `PlaybackProgress`: общий выбор серии, порог просмотренности и интервалы пропусков. Не зависят от UI Android.
- `PlaybackPreferences`, `ViewingHistory`: существующие предпочтения и прогресс по UUID, общие для телефона и ТВ.
- `mobile/MobileActivity`, `MobileAdapter`: сенсорная навигация, сетка, полки и карточка тайтла.
- `mobile/MobilePlayerActivity`: сенсорные контролы Media3, качество, скорость, серии, пропуски и жизненный цикл плеера.
- `MainActivity`, `PlayerActivity`: интерфейс с пультом; существующие аккаунты, коллекции и настройки сохранены.

Отдельные Gradle-модули и новые зависимости не добавлены. Общий слой не требует переноса TV-размеров и D-pad навигации на телефон.

## Поведение

На телефоне и ТВ добавлена общая карточка актуального тайтла: вертикальный постер, название, описание и рейтинг из API. Телефон и ТВ имеют разную компоновку карточки. На телефоне обновления представлены горизонтальной полкой; каталог остаётся сеткой. Продолжение просмотра на ТВ идёт перед обновлениями. Ключи строк сохранены, поэтому добавление/удаление полки не меняет идентификаторы остальных строк.

Явно выбранная серия запускается только по своему UUID. Если поток недоступен, другая серия незаметно не подставляется. Автоматическое продолжение учитывает порог просмотренности и доступность потоков в серверном порядке. Блокированные релизы не запускаются. Параллельные нажатия защищены одним активным запросом; при уходе с экрана запрос отменяется.

Телефон имеет обычный launcher, три нижних раздела, поиск, карточки, локальное избранное, серии и похожие тайтлы. Видеоплеер использует сенсорные контролы Media3; сохраняет позицию, освобождает движок в фоне, восстанавливается после пересоздания Activity, учитывает аудиофокус и отключение наушников. При наличии аккаунта прогресс попадает в общую очередь синхронизации.

Постеры в расписании остаются вертикальными, а превью серий используются в широких карточках. Нижняя навигация и верхняя панель учитывают системные отступы; сенсорные действия имеют область минимум 48dp.

## Что проверено локально

- 12 JUnit-проверок: существующие `PlaybackOrderTest`, `HomeNavigationTest` и новые `PlaybackSelectionTest`, `HomeRowsTest`. Они скомпилированы из production-исходников и выполнены напрямую доступным Kotlin/JVM-компилятором и JUnit; все прошли.
- `aapt2 compile` / `aapt2 link`: ресурсы и manifest проходят проверку доступным Android SDK 37. Это не замена сборке проекта под SDK 36.
- `git diff --check`: без ошибок.

Стандартная Gradle-сборка проекта не выполнена: Gradle 9.1 и AGP 9.0 не доступны в локальном кеше, их загрузка блокируется сетью. Дополнительный проход Kotlin по production-исходникам с доступными кешированными AndroidX/Media3 зависимостями остановился на отсутствующей существующей зависимости `coil3.svg.SvgDecoder`. Он не считается успешной полной компиляцией проекта. Версии зависимостей проекта под эту среду не менялись.

В CI добавлен запуск для рабочей ветки и сохранение APK для обеих платформ. Первый запуск CI (`33dd2189`) успешно скомпилировал приложение, выполнил `testDebugUnitTest`, включая новую Robolectric-проверку `MobileNavigationTest`, и собрал release APK. Общий результат был failure из-за одного NewApi в мобильной теме: параметр API 27 при minSdk 26. Параметр удалён. Повторный CI для актуального кода с карточкой главной (`d5feaa5b`, [run 40379153391](https://github.com/ivan-s-2001/anilibria-app/actions/runs/40379153391)) завершился успешно: `testDebugUnitTest`, `lintDebug`, `assembleDebug`, `assembleRelease`. Debug APK и отчёты с release APK опубликованы в артефактах этого запуска. Новая проверка `HomeHeroViewTest` также вошла в успешный прогон. Проверка `MobileNavigationTest` покрывает телефонную сетку, переход в тайтл, возврат и компоновку в двух ориентациях.

## Следующий этап

Довести общий визуальный язык главной, карточки и плеера на обоих устройствах по YummyTV; проверить экраны на реальном телефоне и телевизоре. У телефона пока нет экрана входа, управления серверными коллекциями, загрузок и PiP. Библиотека телефона пока локальная. Финальный брендинг и миграция namespace — отдельный шаг.

Визуальная проверка на маленьком телефоне, с большим системным шрифтом, и реальное управление пультом ещё не выполнены. Этот этап следует проверять как основу реализации, а не как готовую замену YummyTV.

## Установка Preview 0.2.1

Для устранения конфликта установки application ID изменён с `tv.aniliberty.next` на `app.anihall.preview`, имя в launcher — AniHall Preview. Namespace исходников остаётся `tv.aniliberty.next`; Android Gradle Plugin сохраняет полные имена Activity в итоговом manifest. Старая установка не удаляется и её данные не мигрируются.

Выдаваемая Preview подписывается постоянным приватным ключом, который хранится отдельно от репозитория. CI debug APK использует отдельный пакет `app.anihall.preview.ci`, имя AniHall Preview CI и собственную debug-подпись; он не обновляет и не конфликтует с установленной Preview. Для очередного выдаваемого APK нужно подписывать unsigned release тем же приватным ключом; ключ в git не хранится.
